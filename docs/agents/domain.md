# Domain docs

Use one domain context for Aweille. The workspace package split separates business logic from application adapters.

Before exploring or designing domain behavior, read the root `CONTEXT.md` if it exists and relevant ADRs in `docs/adr/` if present. If these documents do not exist, proceed. Domain-modeling creates them when terms or decisions are resolved.

`CONTEXT.md` is a domain glossary. Use its terms in issues, designs, code, and tests. When a term is missing or used differently, raise the ambiguity and record the agreed meaning through domain-modeling.

ADRs record decisions with meaningful reversal cost, surprising context, and a real tradeoff. If proposed work contradicts one, identify the conflict before proceeding.
